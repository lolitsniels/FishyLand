# RCA — Deploy run 45d03e0a-efd4-41a3-8995-b883f8a1aa96 (fishing-realm)

## Summary
Redeploy failed at the **build_image** step — specifically at the **image push to ECR**, NOT at compile. This is a platform-side registry capacity limit, not an app/source/manifest/secret/tier problem.

## Evidence (verbatim from the failed run)
```
build errors (failed step #51):
ERROR: failed to push 287883095218.dkr.ecr.us-west-2.amazonaws.com/customers-app:45d03e0a-efd4-41a3-8995-b883f8a1aa96: denied:
The repository with name 'customers-app' in registry with id '287883095218' already has the maximum allowed number of images which is '500000'
(type: TerminalCloudBuildFailure, retryable: false)
```

## Root cause
The shared AWS ECR repository `customers-app` (registry `287883095218`, us-west-2) has reached its hard ceiling of **500,000 images**. AWS denied the push for this run's image tag. Because the source compiled and the image built, the ONLY failing operation is the registry push.

## Why this is not the app's fault
- The image built successfully; failure is on `docker push`, an infrastructure operation.
- The three immediately-preceding redeploys for this same job (8904db9c, 78679495, 613de389) pushed to the SAME repo and succeeded. No change in this app's code, manifests, secrets, or tier caused this.
- The live app (active run 8904db9c, https://fishing-realm.emergent.host) is unaffected and still serving.

## Fix (Platform — Emergent infra)
Reclaim space in / raise the limit on the ECR repository `customers-app` (287883095218, us-west-2):
- Apply/execute an ECR lifecycle policy to expire untagged and old images, or
- Raise the repository image-count quota.
Once the repo is below the 500,000 limit, re-fire the deploy. No source, manifest, secret, or tier change is required or would help.

## What I did NOT do
- Did not edit manifests (this is not a manifest-caused failure).
- Did not call resume_pipeline — it would re-hit the identical `denied` push error until the registry is cleaned up.
