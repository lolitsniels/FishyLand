# RCA — Deploy run 2a67634a-a057-41c7-b15c-6a1db19fbb37 (fishing-realm)

## Summary
Redeploy failed at the `build_image` step — but NOT because of the app's source, manifests, secrets, or tier. The container image **built successfully** and failed only when pushing to the AWS ECR registry, which has reached its hard capacity limit.

## Evidence (verbatim from the failed run)
```
build errors (failed step #51):
ERROR: failed to push 287883095218.dkr.ecr.us-west-2.amazonaws.com/customers-app:2a67634a-a057-41c7-b15c-6a1db19fbb37:
denied: The repository with name 'customers-app' in registry with id '287883095218'
already has the maximum allowed number of images which is '500000'
(type: TerminalCloudBuildFailure, retryable: false)
```

The immediately prior run (`45d03e0a-efd4-41a3-8995-b883f8a1aa96`) failed with the byte-identical error, confirming this is a persistent registry-capacity condition, not a transient fluke.

## Root cause
The shared ECR repository `customers-app` (account `287883095218`, region `us-west-2`) has hit the maximum allowed number of images = **500,000**. ECR therefore `denied` the push of the newly-built image. The failure is flagged `retryable: false` / `TerminalCloudBuildFailure`.

## Why no self-service fix applies
- Not source: compile/build phases passed; failure is purely at `docker push`.
- Not manifest: no Dockerfile / entrypoint / nginx change affects a registry quota.
- Not secrets / tier / Mongo: unrelated.
- Re-running `resume_pipeline` will reproduce the same `denied` error (as the prior run already proved).

## Current production state
The deployment is **still LIVE and healthy** on the last successful run `8904db9c-e44f-4a6c-8769-97c2dcd48833`, serving `https://fishing-realm.emergent.host`. Only publishing of the NEW code is blocked.

## Required fix (Platform / Emergent infra)
Reclaim capacity in the `customers-app` ECR repo (`287883095218`, `us-west-2`): prune untagged/old images and/or apply an ECR lifecycle policy to cap retained images, then retrigger the deploy. This requires registry-admin access that the deployer agent does not have.
